# v2.1.3 (`REQ-213`) — Independent Oracle & Real Consumer Verification Protocol (`AC-213-P0-3`)

- **Requirement ID**: `REQ-213` (`AC-213-P0-3`)
- **Governance**: LACD v1.0.2 (`bind_to_commit_sha=true`, `fail_closed=true`)
- **Public/Private Boundary**: Public `cba-kb-engine` repository contains deterministic verification code and clean-room synthetic schemas ONLY. Real authorized player slices, Drive file IDs, and verbatim `ChatGPT Web + Drive Connector` client receipts MUST remain strictly inside the private evidence boundary (`CBA_kb_instance` / private validation vault); public reports record SHA-256 digests and fingerprints only.
- **Debt Boundary**: Open `REQ-212` obligations (`#235`, `#237`, historical Drive ID ACL disposal, v2.1.2 Release GO) remain tracked under `REQ-212` and are NOT closed or repackaged by this protocol.

## 1. Pre-Execution Independent Oracle Freeze Rules

Before running any prompt in `ChatGPT Web + Drive Connector`:

1. **Primary-Source Derivation**: Every `OracleQuestion` (`expected`, `unit`, `precision`, `tolerance`, `required_scope_tokens`, `expected_posture`, `designated_locators`) MUST be fixed from primary official records / registered documents **prior to client execution** (`build_oracle(...)`).
2. **Six-Tuple `ScoringApproval` Pinning**:
   - `manifest_digest`: `oracle.artifact_digest` (64-hex SHA-256)
   - `version`: `oracle.version`
   - `scoring_code_sha`: `cba_kb.oracle.scoring_code_sha()` bound to the exact engine commit SHA
   - `snapshot_digest`: `snapshot.content_sha256` from the verified projection (`verify_local_projection(output_dir)["valid"] is True`)
   - `authorization_domain`: authorized target slice domain
   - `locator_set_digest`: `locator_set_digest(snapshot_locators(snapshot))`

## 3. Verbatim Client Receipt Capture & Formal Verification

1. Execute the fixed question prompts in **`ChatGPT Web + Google Drive Connector`** against the authorized projection (`research_card.md` + backing slice/passage artifacts).
2. Record each response **verbatim** (never summarized, never `SUMMARY_ONLY`, never `REAL_CLIENT_NOT_EXECUTED`) in the private evidence store as `ClientReceipt`:
   - `engine_sha`: exact 40-hex commit SHA of `cba-kb-engine`
   - `snapshot_digest`: 64-hex `content_sha256`
   - `manifest_digest`: 64-hex `oracle.artifact_digest`
   - `question_set_version`: `oracle.version`
   - `authorization_domain`: bound domain
   - `question_id`: `OracleQuestion.question_id`
   - `verbatim_answer`: exact unmodified client answer text
   - `cited_locators`: tuple of locators cited by the client
   - `receipt_mode`: `"VERBATIM"`
3. Validate and score every receipt via the formal approved entrypoints:
   ```python
   errors = validate_receipt_approved(
       receipt,
       oracle=oracle,
       approval=approval,
       snapshot_digest=snapshot_digest,
       authorization_domain=authorization_domain,
       authorized_locators=authorized_locators,
   )
   assert errors == []

   verdict = score_answer_approved(
       question,
       {
           "text": receipt.verbatim_answer,
           "value": extracted_structured_value,
           "unit": question.unit,
           "cited_locators": list(receipt.cited_locators),
       },
       oracle=oracle,
       approval=approval,
       snapshot_digest=snapshot_digest,
       authorized_locators=authorized_locators,
   )
   ```
4. **Repeat & Adjudication Rule**: If repeated runs disagree on `(verdict, dimension, critical)` (`repeat_required(results) is True`), execute at least 3 total runs (`adjudicate_repeat(results, minimum_runs=3)`). Never average conflicting runs into a `PASS`.
5. **Serving Comparison Diagnostics (Non-Gate Measurement)**: Compare `research_card.md` vs raw `answer.json` byte/token size, citation hit rate, and `end_marker: true` survival on real Connector reads. Until real Connector execution is completed in the private workspace, record real-client execution status honestly as `REAL_CLIENT_NOT_EXECUTED` outside `ClientReceipt` (never as a synthetic `PASS`).
